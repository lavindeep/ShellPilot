# Phase 0.5 Model Capability Benchmark — qwen3.5:4b-mlx

Date: 2026-06-12
Script: `scripts/benchmark_model.py` (standalone, live Ollama; never run in CI)
Settings: `num_ctx=8192`, `temperature=0.2`, Ollama current, macOS (Darwin 25.6.0)

This benchmark gates the section 12.5 edit strategy per design section 27.2:
if exact-span reproduction fails more than ~20% of the time, anchored
`replace_exact`-style edits must be replaced with line-window edits or
small-file whole rewrites.

## Results

### a) Tool-call format reliability (10 trials per tool)

| Tool | Well-formed rate |
|---|---|
| `read_file` | 10/10 |
| `list_dir` | 10/10 |
| `search_text` | 10/10 |
| `write_file` | 10/10 |
| `patch_file` | 10/10 |
| `run_command` | 10/10 |
| `env_info` | 10/10 |

Well-formed means: exactly one tool call, correct tool name, all required
arguments present with correct JSON types.

### b) Exact-span reproduction (15 trials over 3 targets)

**15/15** (one target required whitespace-trim rescue). Targets were three
Python functions of increasing trickiness (nested quotes, internal blank line,
operators), reproduced via the `old` argument of a `patch_file` call.

Note: the `subtotal` target matched with whitespace-trim normalisation rather
than byte-exact. The anchored-edit strategy's one-retry loop (section 12.4)
would catch this; byte-exact rate is therefore ~14/15 in the worst case.

### c) Multi-turn chaining (5 chains × 6 steps)

**1/5 chains fully intact.** Per-step rates: `[1.0, 1.0, 1.0, 1.0, 0.4, 0.2]`.
Step 5 rate: 0.4. The model handles steps 1–4 reliably but loses coherence at
steps 5–6. This is a meaningful regression versus gemma4:e4b (5/5 chains
intact).

### d) Stopping behavior (10 trials each)

- Plain question with all 7 tools offered: answered in text without tool calls 10/10.
- After a completed 1-tool task: produced a final text answer (no extra calls) 10/10.

## Gate decision

**Exact-span failure rate: ~6.7% (1 whitespace-trim rescue out of 15; threshold: ~20%).
The anchored edit strategy in design section 12.5 stands for qwen3.5:4b-mlx.**

Multi-turn chaining degrades at step 5+. This is a model quirk (not a harness
bug); the multi-step plan loop is gated by the harness continuation logic, not
by model chain coherence alone.

## Caveats

- Temperature 0.2 and a small synthetic corpus (one ~30-line file, three span
  targets). Real-world files are longer and noisier; the read-before-write
  snapshot validation and one-retry recovery loop (sections 10.4, 12.4) remain
  load-bearing regardless of these scores.
- `num_ctx=8192`; long-context degradation was not measured here.
- Multi-turn chaining at steps 5–6 is notably weaker than gemma4:e4b. For
  complex multi-step plans, gemma4:e4b is the recommended model.
